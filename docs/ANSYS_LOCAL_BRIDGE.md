# ANSYS Local Bridge — Phase 1

## Scope

Phase 1 introduces a connection boundary only. It does **not** discover, launch, license, script, or run ANSYS. The adapter is deliberately `mock`, reports `ansysConnected: false` and `simulationsEnabled: false`, and exposes no simulation endpoint.

The bridge is a separate FastAPI package under `services/ansys_bridge`. It is not imported by `api/index.py`, is excluded from the Vercel Python function bundle, and must run on the engineer's own computer.

## Security boundary

- The supported launcher binds Uvicorn to `127.0.0.1:8765`; it never binds to a LAN or public interface.
- Middleware rejects any socket client that is not loopback and rejects browser origins outside the configured allowlist.
- Protected status requests require a random, per-process token in the `X-MSKU-Bridge-Token` header.
- The frontend accepts only HTTP loopback bridge URLs. Remote hosts, credentials, query strings, fragments, and endpoint paths are rejected.
- The token is stored in browser `sessionStorage`, not local project data, cookies, exports, the engineering API, or Vercel.
- Private Network Access preflight is allowed only after the exact browser origin and requested header pass CORS checks.
- Access logs are disabled by the supported launcher to reduce accidental local metadata exposure.

The unauthenticated liveness endpoint returns only the bridge identity, version, localhost scope, and whether a token is configured. It does not reveal a token, filesystem path, ANSYS installation, license state, project data, or simulation data.

## Run locally

Install the workspace dependencies once:

```powershell
uv sync --all-packages --all-extras --dev
```

Start the bridge:

```powershell
npm run ansys-bridge:dev
```

The launcher creates a cryptographically random token when `MSKU_ANSYS_BRIDGE_TOKEN` is not already set. Copy the printed token into **ANSYS YEREL** in the application header. The bridge address is fixed at `http://127.0.0.1:8765`.

For a controlled token, set a secret of at least 32 characters before starting:

```powershell
$env:MSKU_ANSYS_BRIDGE_TOKEN = "replace-with-a-random-secret-of-32-or-more-characters"
npm run ansys-bridge:dev
```

Do not put the token in a committed `.env` file. Restarting without a fixed environment token creates a new token and invalidates the previous browser session value.

## HTTP contract

| Method | Path | Authentication | Purpose |
| --- | --- | --- | --- |
| `GET` | `/bridge/v1/health/live` | Loopback socket + allowed Origin | Minimal process liveness and secure-configuration state |
| `GET` | `/bridge/v1/health/ready` | Loopback socket + allowed Origin + token | Bridge/mock readiness without claiming ANSYS readiness |
| `GET` | `/bridge/v1/status` | Loopback socket + allowed Origin + token | Mock adapter status and explicit Phase 1 limitations |

There are intentionally no job, solve, upload, filesystem, command-execution, or ANSYS-control endpoints.

## Configuration

| Environment variable | Default | Meaning |
| --- | --- | --- |
| `MSKU_ANSYS_BRIDGE_TOKEN` | Generated by supported launcher | Required header secret; minimum 32 characters |
| `MSKU_ANSYS_BRIDGE_ALLOWED_ORIGINS` | Local Vite/preview origins and official production site | Comma-separated exact browser origins |

Changing allowed origins does not change the loopback socket restriction. A future real adapter must retain these boundaries, add an explicit user-confirmed job model, validate all paths and payloads, and receive separate engineering verification before use.

## Verification

Automated tests cover liveness, authenticated readiness, mock-only status, missing/invalid token rejection, unconfigured-token rejection, untrusted-origin rejection, Private Network Access preflight, and remote-socket rejection. Frontend tests cover strict loopback URL validation, token-required state, mock contract acceptance, and authorization failure classification.

This verifies the Phase 1 software boundary; it is not evidence that ANSYS is installed, connected, licensed, or physically validated.
