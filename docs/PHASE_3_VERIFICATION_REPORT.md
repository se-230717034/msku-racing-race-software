# Phase 3 verification report

Date: 2026-10-15  
Quasi-static solver: `3.0.0`  
Quality: `REFERENCE_BENCHMARKED` / `UNVALIDATED_PHYSICALLY` / `NOT_APPROVED`

## Purpose

This report records reproducible numerical evidence for the Phase 3 quasi-static implementation.
Expected values below were derived directly from equilibrium, rigid-body load transfer, or spring
energy equations and were not generated by the production solver. Passing tests establish software
behaviour for the stated cases; they do not establish vehicle accuracy, part strength, or safety.

## Reference cases and quantitative results

| Case | Independent expectation | Actual result | Discrepancy/status |

The six-member basis was constructed independently as columns `Fx`, `Fy`, `Fz`, `Fz+Mx`,
`Fx+My`, and `Fy+Mz`. This makes all expected wrench components available by hand summation and
avoids using the solver to manufacture expected results.

## Failure and safety-path coverage

- Every vector and scalar must be finite; member IDs must be nonempty and unique.
- Members shorter than `1e-6 m` fail before matrix solution.
- SVD rank and condition checks use the dimensionless wrench matrix.
- A least-squares termination flag is not an acceptance criterion. Original N/N·m residuals are
  recomputed and compared with independent tolerances.
- An incompatible five-member contact wrench returns no axial forces.
- More than six unknown axial forces return no arbitrary minimum-norm engineering result.
- Missing lateral roll stiffness suppresses wheel loads while retaining supported axle loads.
- Negative axle/wheel loads fail and are not returned as valid distributions.
- Spring series require three or more finite, strictly increasing travel samples and matching
  positive lengths.
- Compression-only spring tension and missing damper velocity are `NOT_COMPUTABLE`.
- Approved export remains disabled for all Phase 3 UI results.

## What is verified, benchmarked, and unvalidated

`VERIFIED_NUMERICALLY` means the individual request passed input, matrix-quality, residual, and
physical-domain checks. `REFERENCE_BENCHMARKED` means solver version `3.0.0` passes the repository
analytical cases above. `UNVALIDATED_PHYSICALLY` means no independent MSKU Racing CAD force study,
instrumented rig, load-cell, damper-dyno, corner-weight, or on-vehicle data has been attached.

The current evidence does not validate:

- real pickup coordinates, masses, CG, roll stiffnesses, spring rates, preload, or tyre loads;
- wishbone tube stresses, joint/bearing/fastener loads, buckling, fatigue, or safety factors;
- compliance, friction, hysteresis, bump stops, anti-roll bars, unsprung mass, aerodynamic loads,
  geometric jacking, or tyre constitutive behaviour;
- integrated rocker kinematics from the stored optional coordinates;
- transient response or damper force without measured/declared velocity.

## Remaining validation plan

1. Import reviewed MSKU CAD hardpoints and actuation coordinates with measurement uncertainty.
2. Cross-check link forces against an independent CAD/multibody static study for several measured
   contact wrenches, recording tool version, boundary conditions, units, and input hashes.
3. Compare spring travel/motion ratio with CAD motion study and physical displacement measurements.
4. Compare static corner weights and controlled longitudinal/lateral transfer with calibrated load
   measurements, including uncertainty bounds.
5. Add structural FEA or hand calculations in a separate model before interpreting ideal axial
   forces as component capacity.
6. Keep physical status `UNVALIDATED_PHYSICALLY` and approval `NOT_APPROVED` until reviewed evidence
   is attached and signed off by the team.
